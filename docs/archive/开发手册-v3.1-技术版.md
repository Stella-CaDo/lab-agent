4. **地基不回头**：地基合入后除非发现真 bug，否则不重构。想优化写法，先记在自己的备忘录里，交付后再说。

### 0.6 作业要求对照与网络请求说明

**作业原文要点**：自选主题，做一个 Vue3 单页应用（SPA）；综合运用数据绑定、组件、路由、网络请求、状态管理等知识；结合 Element Plus 这类 UI 组件库；灵活设置多个功能页面（仪表盘首页、数据管理页、统计图表页等）；实现数据显示、图表统计、新增、编辑、删除、查询等常用功能。

| 作业要求 | 本项目落点 |
|---|---|
| Vue3 单页应用 | Vite + Vue 3 + vue-router（history），6 个业务页共用 `Layout`，登录 / 404 独立 |
| 数据绑定 | 搜索条件 / 表单 `v-model`、表格列、图表 `computed option` |
| 组件 | 4 个公共组件 + 各页面私有组件 |
| 路由 | 嵌套路由、登录守卫、`redirect` 回跳、404 |
| 网络请求 | axios 实例 + 拦截器 + 7 个 api 模块 + 浏览器 mock（见下） |
| 状态管理 | Pinia：`lab` / `reservation` / `auth` 三个 store |
| UI 组件库 | Element Plus：表格 / 分页 / 抽屉 / 弹窗 / 表单 / 标签 / 菜单 |
| 多页面 | 首页、预约、实验室、设备、用户、统计、登录 |
| 数据显示 | 表格 + 状态标签 + 空态 + loading |
| 图表统计 | ECharts：趋势、使用次数、状态占比、热力图（共 6 张图） |
| 增删改查 / 查询 | 实验室完整 CRUD；预约提交/审核/取消；关键字 + 筛选 + 分页 |

**网络请求方案（已定：A 方案）**

- 代码形态和真实后端一致：`axios.create({ baseURL: '/api', adapter: mockAdapter })` + 请求/响应拦截器 + `api/lab.js` 这类 REST 模块，页面只调 `getLabList()`。
- 唯一区别在最后一跳：`mockAdapter` 把请求交给浏览器内的 mock，不发真实 HTTP；数据读写 `localStorage`。
- 为什么这样定：题目自选主题、没有后端要求；这样 `npm run build` 之后仍是完整 SPA，拷走静态文件就能演示。
- **答辩话术**（照这三句说）：
  1. 网络层用 axios 统一封装：baseURL、超时、token 注入、业务码判断、错误提示都在拦截器里，接口按 REST 风格拆成 7 个模块。
  2. 因为没有后端，我用 axios 自定义 adapter 把请求接到浏览器内的 mock，数据持久化到 `localStorage`，相当于把"服务端"换成了适配器。
  3. 所以 Network 面板里没有请求，但 axios 的请求/响应链路、loading、错误处理都是真实生效的。
- **兜底**：万一老师坚持要在 Network 里看到 XHR，可切换 MSW（Mock Service Worker）——仍是纯前端 + `localStorage`，只改 mock 层和 `main.js`，页面与 `api/*.js` 不动。当前不启用，避免多一个 Service Worker 依赖。

> 可选扩展（不占主干）：CSV 导出、登录后首页问候语。主题切换、日历视图这类费时的，不建议加。

### 1.2 接口契约（唯一真相，页面全部按这张表写）

#### 1.2.1 通用约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api`，前端 axios 里配 `baseURL: '/api'`，页面只写 `/labs` 这种相对路径 |
| 请求方式 | **不发真实 HTTP 请求**：`request.js` 配了 `adapter: mockAdapter`，所有 `/api/*` 在浏览器内处理 |
| 成功响应 | `{ "code": 0, "msg": "ok", "data": ... }` |
| 业务失败 | `{ "code": 1, "msg": "中文提示", "data": null }`（HTTP 层面永远是 200） |
| 资源不存在 | `{ "code": 1, "msg": "xxx不存在" }` |
| 分页入参 | `page`（从 1 开始）、`size`（默认 10） |
| 分页出参 | `{ "list": [], "total": 0, "page": 1, "size": 10 }` |
| 日期格式 | `YYYY-MM-DD`（如 `2026-11-06`） |
| 时间格式 | `HH:mm` 24 小时制（如 `08:30`） |
| 鉴权 | mock 不校验 token；登录只用于前端路由守卫。`userId` 可选，缺省按 1 处理 |
| 数据存储 | `localStorage` 的 `lab_db_v1`，结构 `{ version, labs, users, devices, reservations }`，首次自动种子 |
| 调试入口 | dev 下控制台有 `window.__labMock`（`get/post/put/del/reset/dump`），见 1.10 |
| 模拟延迟 | 每个请求 80–200 ms，页面的 `loading` 状态能看出来 |

> **错误提示只弹一次**：`src/api/request.js` 的拦截器已经把 `msg` 用 `ElMessage.error` 弹出来了。页面的 `catch` 里**不要再弹**，写个注释就行。

#### 1.2.4 关键请求体与失败场景

**新增 / 修改实验室**

```json
{
  "name": "软件工程实验室",
  "building": "A栋",
  "room": "A401",
  "capacity": 50,
  "openTime": "09:00",
  "closeTime": "21:00",
  "status": "available",
  "remark": "双屏工位"
}
```

| 失败场景 | 返回 `msg` |
|---|---|
| 名称为空 | 实验室名称不能为空 |
| 容量不是 1–200 | 容量必须是 1 到 200 之间的数字 |
| 楼栋为空 | 请选择所属楼栋 |
| 结束 ≤ 开始 | 开放时间：结束必须晚于开始 |
| 删除时还有待审核预约 | 该实验室还有待审核预约，不能删除 |

**提交预约**

```json
{
  "labId": 1,
  "userId": 2,
  "date": "2026-11-08",
  "startTime": "14:00",
  "endTime": "16:00",
  "purpose": "课程实验",
  "attendees": 30
}
```

| 失败场景 | 返回 `msg` |
|---|---|
| 实验室不存在 | 实验室不存在 |
| 实验室非可用 | 该实验室当前不可预约 |
| 缺日期 / 时段 | 请选择预约日期和时段 |
| 日期早于今天 | 不能预约过去的日期 |
| 结束 ≤ 开始 | 结束时间必须晚于开始时间 |
| 超出开放时间 | 预约时段超出实验室开放时间 08:00-21:00 |
| 人数超容量 | 预约人数不能超过实验室容量 60 |
| 时段重叠 | 时段冲突：14:00-16:00 已被占用 |

> 冲突判定规则：**同实验室 + 同日期 + 时段重叠 + 状态是待审核或已通过**。判定公式 `aStart < bEnd && bStart < aEnd`。

**状态流转**（第 9 号接口只允许这三种）

| 当前状态 | 允许改成 | 不合法时返回 |
|---|---|---|
| `pending` | `approved` / `rejected` | 当前状态不允许这样流转 |
| `approved` | `cancelled` | 当前状态不允许这样流转 |

// 响应拦截：code 为 0 才算成功，直接把 data 返回给业务层

  (response) => {
    const body = response.data
    if (body && body.code === 0) return body.data

    ElMessage.error(msg)

  (error) => {
    const data = error.response && error.response.data
    const msg = (data && data.msg) || error.message || '网络异常'
    ElMessage.error(msg)
    return Promise.reject(error)
  }
)

import { defineStore } from 'pinia'
import { ref } from 'vue'
import { getLabList, createLab, updateLab, deleteLab } from '@/api/lab'

export const useLabStore = defineStore('lab', () => {
  const list = ref([])
  const total = ref(0)
  const loading = ref(false)
  // 查询条件放 store，页面只负责 v-model 绑定
  const query = ref({ keyword: '', building: '', status: '', page: 1, size: 10 })

  async function fetchList(extra = {}) {
    loading.value = true
    try {
      const data = await getLabList({ ...query.value, ...extra })
      list.value = data.list
      total.value = data.total
    } finally {
      loading.value = false
    }
  }

  /** 有 id 走修改，没有走新增；表单里的 id 不发给 mock */
  async function saveLab(form) {
    const { id, ...payload } = form
    if (id) await updateLab(id, payload)
    else await createLab(payload)
    await fetchList()
  }

  async function removeLab(id) {
    await deleteLab(id)
    await fetchList()
  }

  /** 下拉框用：一次取全部实验室（最多 100 条） */
  async function fetchAllLabs() {
    const data = await getLabList({ page: 1, size: 100 })
    return data.list
  }

  return { list, total, loading, query, fetchList, saveLab, removeLab, fetchAllLabs }
})

## 2. 页面包通用规范

### 2.1 一个页面包包含什么

1. **一个 view 文件**（`src/views/Xxx.vue`），必要时可加 `<页面名><用途>.vue` 私有子组件
2. **一个 commit**，信息格式 `feat(<scope>): <包号> <页面名>（关键词1/关键词2）`
3. **一次完整验收**：该包验收清单逐条手点，全过才提交
4. **可能的话**：截图 1 张放进 `演示截图/`（合流时统一整理）

### 2.2 UI 一致性清单（所有页面照这个来）

| 部位 | 统一做法 |
|---|---|
| 页面外壳 | `<el-card shadow="never">` 包住整页 |
| 页头 | `<PageHeader title="xx管理" desc="一句话说明">`，右侧放主操作按钮 |
| 查询区 | `<SearchBar :loading="..." @search="..." @reset="...">`，里面每个条件一个 `el-form-item` |
| 表格 | `border stripe` + `v-loading` + `#empty` 插槽放 `el-empty` |
| 分页 | `layout="total, sizes, prev, pager, next, jumper"`、`:page-sizes="[10, 20, 50]"`、`background`，外层 `<div class="pager">` |
| 行内操作 | `el-button link type="primary"/"danger"` |
| 删除 | 必须先 `ElMessageBox.confirm`，文案带对象名 |
| 成功提示 | `ElMessage.success('xx成功')` |
| 失败提示 | **不要自己弹**，拦截器已统一弹过 |
| 状态标签 | 一律 `:type="DICT[status].tag"`，文案取 `DICT[status].text`，不要页面里写三元表达式 |
| 空值占位 | `<span class="muted">—</span>` |
| 表单弹层 | `el-dialog` / `el-drawer` 都加 `destroy-on-close` |

> 这条"失败提示不要自己弹"是**最容易被扣分的细节**：如果页面 `catch` 里再 `ElMessage.error`，用户会看到两条一样的红条。

### 2.3 代码约定

- 统一 `<script setup>` + 组合式 API，不要选项式
- 请求放 `onMounted`，不要放 `setup` 顶层（会早于组件挂载）
- 查询条件变化后**页码回 1** 再请求
- 表单提交前 `await formRef.value.validate().catch(() => false)`
- 不要用 `v-if` 藏图表容器（高度会变 0，图表空白）；要藏用 `v-show`
- 页面私有组件命名：`LabForm.vue`、`BookingConflictTip.vue`，前缀 = 页面名，归属一眼可见
- 不新建 store；确实需要跨页共享，先在群里说，由 A 加

### 3.3 新建 `src/stores/auth.js`

```js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { login as loginApi } from '@/api/auth'

/** 容错读取本地用户信息：手动改坏 localStorage 也不至于白屏 */
function readUser() {
  try {
    return JSON.parse(localStorage.getItem('lab_user') || 'null')
  } catch {
    return null
  }
}

export const useAuthStore = defineStore('auth', () => {
  // 从 localStorage 恢复，刷新页面不掉登录
  const token = ref(localStorage.getItem('lab_token') || '')
  const user = ref(readUser())

  const isLogin = computed(() => !!token.value)
  const name = computed(() => (user.value ? user.value.name : '未登录'))

  /** 登录成功后同时写 store 和 localStorage */
  async function login(form) {
    const data = await loginApi(form)
    token.value = data.token
    user.value = data.user
    localStorage.setItem('lab_token', data.token)
    localStorage.setItem('lab_user', JSON.stringify(data.user))
    return data
  }

  /** 退出：清空所有痕迹 */
  function logout() {
    token.value = ''
    user.value = null
    localStorage.removeItem('lab_token')
    localStorage.removeItem('lab_user')
  }

  return { token, user, isLogin, name, login, logout }
})
```

    meta: { public: true }
  }

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes
})

// 全局前置守卫：没登录一律赶去登录页
router.beforeEach((to) => {
  const token = localStorage.getItem('lab_token')
  if (to.meta.public) {
    // 已登录还去登录页，直接进首页
    if (to.path === '/login' && token) return '/manager/home'
    return true
  }
  if (!token) return { path: '/login', query: { redirect: to.fullPath } }
  return true
})

// 动态改浏览器标题
router.afterEach((to) => {
  document.title = to.meta.title ? to.meta.title + ' - 实验室预约系统' : '实验室预约系统'
})

export default router

> `/:pathMatch(.*)*` 必须放在**最后一条**，否则会吃掉所有路由。

### 3.10 坑

- **刷新回登录页**：`localStorage` 的 key 必须和守卫里读的完全一致（`lab_token`）。
- **登录后一直跳登录页**：守卫里 `to.meta.public` 判断写反了，或者 login 路由漏了 `public: true`。
- **404 不生效**：catch-all 没放最后，或者写成了 `/:pathMatch(.*)` 漏了 `*`。
- **顶栏不刷新用户名**：`Layout` 里用了 `auth.name` 的 computed，别自己再存一份字符串。

### 4.3 新建 `src/stores/reservation.js`

```js
import { defineStore } from 'pinia'
import { ref } from 'vue'
import {
  getReservationList,
  createReservation,
  changeReservationStatus,
  deleteReservation
} from '@/api/reservation'

export const useReservationStore = defineStore('reservation', () => {
  const list = ref([])
  const total = ref(0)
  const loading = ref(false)
  const query = ref({ status: '', date: '', labId: '', page: 1, size: 10 })

  async function fetchList(extra = {}) {
    loading.value = true
    try {
      const data = await getReservationList({ ...query.value, ...extra })
      list.value = data.list
      total.value = data.total
    } finally {
      loading.value = false
    }
  }

  /** 提交后自动刷新列表 */
  async function submit(form) {
    const record = await createReservation(form)
    await fetchList()
    return record
  }

  async function changeStatus(id, status) {
    await changeReservationStatus(id, status)
    await fetchList()
  }

  async function remove(id) {
    await deleteReservation(id)
    await fetchList()
  }

  return { list, total, loading, query, fetchList, submit, changeStatus, remove }
})
```

/** 前端预校验：查同实验室同日期已有预约，判断是否重叠 */
async function findConflict() {
  const data = await getReservationList({ labId: form.labId, date: form.date, page: 1, size: 200 })
  return data.list.find(
    (r) =>
      (r.status === 'pending' || r.status === 'approved') &&
      form.startTime < r.endTime &&
      r.startTime < form.endTime
  )
}

async function handleSubmit() {
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return

  saving.value = true
  try {
    // 第一步：前端先拦，用户立刻得到反馈
    const conflict = await findConflict()
    if (conflict) {
      ElMessage.warning('时段冲突：' + conflict.startTime + '-' + conflict.endTime + ' 已被占用')
      return
    }
    // 第二步：真正提交，mock 层还会再校验一次（双层拦截）
    await store.submit({ ...form, userId: auth.user ? auth.user.id : 1 })
    dialogVisible.value = false
    ElMessage.success('提交成功，等待审核')
    // 切到待审核并清掉筛选，保证新记录一定能看到
    store.query.status = 'pending'
    store.query.date = ''
    store.query.labId = ''
    store.query.page = 1
    await store.fetchList()
  } catch {
    // 错误提示由拦截器统一弹出
  } finally {
    saving.value = false
  }
}

/** 审核 / 取消 */
async function handleChange(row, status, label) {

  try {
    await ElMessageBox.confirm(tip, '确认操作', { type: 'warning' })
  } catch {
    return
  }
  try {
    await store.changeStatus(row.id, status)
    ElMessage.success(label + '成功')
  } catch {
    // 拦截器已提示
  }
}
</script>

### 7.4 数据流与 store 契约（直接用，不要自己写请求）

`useLabStore()` 已经把查询条件、列表、增删改都封好了：

| 成员 | 类型 | 说明 |
|---|---|---|
| `store.list` | `ref<Lab[]>` | 当前页数据 |
| `store.total` | `ref<number>` | 总条数 |
| `store.loading` | `ref<boolean>` | 请求中 |
| `store.query` | `ref<{ keyword, building, status, page, size }>` | 查询条件，页面用 `v-model` 直接绑 |
| `fetchList(extra?)` | `async (extra?: object) => void` | 按当前 `query` 拉一页；`extra` 可临时覆盖条件 |
| `saveLab(form)` | `async (form) => void` | **有 `id` 走修改，无 `id` 走新增**；自动刷新列表 |
| `removeLab(id)` | `async (id) => void` | 删除并刷新列表 |
| `fetchAllLabs()` | `async () => Lab[]` | 拉全部（最多 100 条），给下拉用；**不影响 `store.list`** |

页面里只做四件事：

1. `onMounted(() => store.fetchList())`
2. 查询：`store.query.page = 1` 后 `store.fetchList()`
3. 重置：把 `keyword/building/status` 清空、`page = 1` 后 `store.fetchList()`
4. 保存/删除：`await store.saveLab({ ...form })` / `await store.removeLab(row.id)`，成功后 `ElMessage.success`

> 表单里可以保留 `id: null`，`saveLab` 会自动剥掉，不会把 `null` 发给 mock。

### 7.5 接口契约（你只用到这 5 个）

**GET `/api/labs`** — 分页查询

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | string | 否 | 模糊匹配名称 / 房间号 / 楼栋 |
| `building` | string | 否 | 精确匹配 `A栋` / `B栋` / `C栋` |
| `status` | string | 否 | `available` / `maintenance` / `disabled` |
| `page` | number | 否 | 从 1 开始 |
| `size` | number | 否 | 默认 10 |

响应 `data`：

```json
{
  "list": [
    {
      "id": 1,
      "name": "计算机基础实验室",
      "building": "A栋",
      "room": "A201",
      "capacity": 60,
      "openTime": "08:00",
      "closeTime": "21:00",
      "status": "available",
      "remark": "60 台高性能 PC"
    }
  ],
  "total": 8,
  "page": 1,
  "size": 10
}
```

**POST `/api/labs`** — 新增。请求体：`name` `building` `room` `capacity` `openTime` `closeTime` `status` `remark`（**不要带 `id`**）。成功返回新对象，`msg:"新增成功"`。

**PUT `/api/labs/:id`** — 修改。请求体同新增。成功 `msg:"修改成功"`。

**DELETE `/api/labs/:id`** — 删除。成功 `msg:"删除成功"`。

**失败场景**（页面不用处理，拦截器会弹；但验收要知道预期）：

| 触发 | 提示 |
|---|---|
| 名称空 / 容量越界 / 楼栋空 / 结束 ≤ 开始 | 对应中文提示 |
| 删除还有待审核预约的实验室 | 该实验室还有待审核预约，不能删除 |

### 7.9 坑

- **新增后列表里没有**：`saveLab` 会自动刷新；8+1=9 条还在第 1 页末尾，超过 10 条后新记录才会出现在最后一页，别以为没保存成功。

### 11.1 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面数据为空、Console 没有 `[API]` 日志 | `request.js` 没挂 `adapter: mockAdapter` | 按 1.5 补上 import 和 adapter 配置 |
| 页面提示「接口不存在」 | 路径写错，比如写成了 `/api/labs` | 页面里只写 `/labs`（adapter 按这个路径匹配），不要带 `/api` 前缀 |
| `getActivePinia() was called but there was no active Pinia` | `main.js` 没注入 pinia，或放在 `router` 之后 | pinia 必须在 router 之前 |
| 页面空白、终端报 Failed to fetch dynamically imported module | 某个 `.vue` 编译失败 | 看终端报错指出的文件，多半是标签没闭合 |
| 新增后编辑报「实验室不存在」 | 表单把 `id: null` 发给 mock 了 | 用 `store.saveLab`，它剥 `id` |
| 删除实验室失败 | 该实验室还有待审核预约 | 业务保护，不是 bug |
| 图表空白 | 容器高度 0，或父元素 `v-if` 隐藏 | 传 `height`，隐藏用 `v-show` |
| 切 tab 后图表变形 | 隐藏时宽度 0 | `ChartBox` 的 `ResizeObserver` 别删 |
| `el-radio` / `el-radio-button` 不生效 | Element Plus 2.6+ 用 `value` 替代 `label` | 按本文档写 `:value` |
| 分页点了没反应 | `@current-change` 没调用函数 | 写 `@current-change="store.fetchList()"` |
| 登录后刷新回登录页 | localStorage key 不一致 | 守卫和 store 都用 `lab_token` |
| 刷新后数据回到 8 条 | 浏览器清了缓存 / 无痕模式 / 换了端口 | 正常；localStorage 按 origin 隔离 |
| 访问 `/login` 被弹回首页 | 已登录守卫逻辑 | 正常行为；要测登录页先退出 |
| 404 页不生效 | catch-all 没放最后 | 放 routes 数组最后 |
| 控制台 `__labMock` 是 undefined | 不是 dev 环境（preview / build 后没有调试入口） | 正常；build 后用页面操作验证 |
| `Port 5173 is in use` | 旧 dev server 没关 | 关旧终端，或用提示的新端口 |
| 合并冲突一堆 | 两人改了同一个公共文件 | 按 0.2 归属表，公共文件归 A |
| 改了种子或 mock 逻辑但数据没变 | localStorage 里存着旧数据，mock 不会自动覆盖 | 右上角「重置演示数据」，或 `__labMock.reset()` |

### 11.2 考点对照（答辩自查）

| 考点 | 落在哪 |
|---|---|
| 数据绑定 | A2 预约表单/筛选、B1 实验室表单/筛选、A3 指标卡 |
| 组件 | 地基 4 个公共组件 + 各页面私有组件 |
| 路由 | A1 路由守卫、redirect 回跳、404 兜底 |
| 网络请求 | 地基 `request.js` 拦截器 + 自定义 adapter + 7 个 api 模块 + 17 个 mock 路由 |
| 状态管理 | 地基 `lab` store、A1 `auth` store、A2 `reservation` store |
| UI 组件库 | 全站 Element Plus（表格/抽屉/弹窗/分页/表单/标签） |
| 多页面 | 7 个页面（6 业务页 + 登录/404）+ Layout 嵌套路由 |
| 图表统计 | A3 2 张图、A4 4 张图（echarts 按需引入） |
| 增删改查 | B1 完整 CRUD、A2 预约提交 + 审核状态流转 |

**答辩可以主动讲的三点**：

1. **双层冲突校验**：前端先查再拦（用户无等待），mock 层再拦一次（防绕过），对应 1.2.4 的冲突公式。
2. **路由守卫 + 重定向**：未登录跳 `/login?redirect=原路径`，登录后回原页面。
3. **echarts 按需引入**：只注册用到的 4 种图表和 4 个组件，打包体积更小。
4. **纯前端数据层**：axios 自定义 adapter 拦截请求，数据落 `localStorage`，不用后端、刷新不丢、`build` 后照样跑。
